# Glossary (one line each)

**ACID:** atomic, consistent, isolated, durable transactions. · **At-least-once:** delivered one or more times (duplicates possible). · **Backpressure:** slowing producers when consumers cannot keep up. · **Bloom filter:** compact set that gives "no" or "maybe". · **Bulkhead:** isolating resources so one failure does not spread. · **Cache-aside:** app reads cache, falls back to DB and fills it. · **CAP:** under a partition, pick consistency or availability. · **CDN:** edge cache close to users. · **Circuit breaker:** stop calling a failing dependency. · **Consistent hashing:** hashing onto a ring so adding nodes moves few keys. · **Consensus (Raft/Paxos):** agreeing on a replicated log. · **CQRS:** separate read and write models. · **CRDT:** data type that merges concurrent edits without conflicts. · **DLQ (dead-letter queue):** where unprocessable messages go. · **Denormalisation:** storing duplicate data to speed reads. · **Eventual consistency:** replicas converge over time. · **Exactly-once:** in practice at-least-once plus idempotency. · **Fan-out:** delivering one event to many targets. · **Fencing token:** monotonic number so a stale lock holder cannot write. · **Gossip protocol:** nodes exchange state peer to peer. · **Hot partition/key:** one shard/key receiving disproportionate load. · **Idempotent:** repeating has the same effect as once. · **Isolation level:** how much concurrent transactions can see each other. · **Lease:** a time-limited lock or ownership. · **Linearizable:** operations appear to happen in one real-time order. · **LSM tree:** write-optimised storage structure. · **Outbox:** event stored in the same transaction as the data, published later. · **PACELC:** partition → A or C; else latency vs consistency. · **Partition key:** decides which shard/partition a record lives on. · **p99:** latency under which 99% of requests complete. · **Quorum:** majority needed for a read/write (R + W > N). · **Rate limiting:** capping requests per time. · **Read replica:** read-only copy of a database. · **Reconciliation:** comparing sources of truth to repair drift. · **Replication lag:** delay before a replica has a write. · **Saga:** multi-step process with compensating actions. · **Sharding:** splitting data across nodes. · **SLI/SLO:** measurement / target for service quality. · **Split brain:** two nodes both think they lead. · **Stampede:** many requests rebuilding a just-expired hot key. · **TTL:** time to live before expiry. · **Two-phase commit:** blocking atomic commit across systems. · **Vector clock:** tracks causality between versions. · **WAL (write-ahead log):** log written before applying changes, for recovery. · **Write skew:** concurrent transactions each read then write different rows, breaking an invariant.
